# ArtCraft 调用漫剧平台生成视频：平台侧协作需求

状态：待平台团队确认；尚未完成运行时联调。

## 1. 目标与责任边界

两个项目独立维护、独立部署，只通过 HTTP API 连接。

- ArtCraft 团队负责：Stage3D 捕获、参数界面、平台 HTTP 客户端、任务跟踪与恢复、结果下载、预览与保存。
- `new-aigc-comfyui-minimax-h3` 团队负责：平台接口及文档、输入校验、任务执行、GPU 调度和输出可访问性。
- ArtCraft 团队不修改平台仓库。平台如需补功能，由平台团队实施。
- 优先复用已有接口；本文件不是要求重做一套 API。已有能力只需确认契约，确实缺失的能力才需要开发。
- ArtCraft 可以先依据确认的样例与模拟服务开发，不必等待所有增强项完成。

首期闭环：

```text
ArtCraft Stage3D 构图 PNG
  → 平台上传
  → 创建 playground 独立视频任务
  → 查询任务
  → 下载结果
  → ArtCraft 预览、保存
```

首期不要求绑定项目、Scene 或 Shot；不要求平台识别 ArtCraft 云端 media token；不要求同步 3D 场景 JSON；不改变已有审核流程。

## 2. 已核查的代码基础

以下来自平台源码静态阅读，不等于已运行验证。路径相对平台仓库，平台团队应以交付版本复核。

- `backend/internal/api/router.go`：已有 model catalog、upload、playground、task、WebSocket 和 output 路由。
- `backend/internal/service/playground_service.go`：`CreatePlaygroundRunInput` 包含 `mode`、`template`、`prompt`、`params`、`files`、`batch_count`。按模板 code 查找启用模板，校验 mode，创建 Task 和 PlaygroundRun；不要求项目绑定。批数默认 1，当前允许 1–4。
- `backend/internal/service/task_service.go`：`FileMeta` 使用 `task_id`、`name`，不是 ArtCraft media token。
- `backend/internal/service/handlers.go`：已有 multipart 上传和支持 Range 的输出读取处理。
- `backend/internal/service/model_catalog.go`：已有基于模板的能力目录，不应另建手工维护的模型能力真源。
- `backend/internal/service/project_handlers.go`：已有 Scene 首尾帧上传及保存字段。但这不是 Shot 级绑定接口，首期独立生成不应依赖它。

仅以上阅读不能确认部署鉴权、完整响应格式、任务幂等、取消、保留期或运行可用性。

## 3. 现有接口契约确认清单（P0）

P0 的含义是首期联调必需，不意味着每项都要新增代码。请求提供脱敏示例或接口文档；已有能力直接复用。

### 3.1 能力目录

接口：`GET /api/model-catalog`。

请确认：

- 模板 code、mode、展示名称、是否启用，以及创建任务时如何引用。
- 首期选定一个接受构图图片的视频模板，优先核验 H3 i2v；最终以真实模板能力为准。
- 图像输入的字段名、角色、数量、必填条件，以及首尾帧和参考输入的互斥关系。
- 时长、分辨率、比例等参数的真实键名、类型、可选值与默认值。
- 已有能力目录能否提供上述信息；若不完整，可补现有目录或交付与模板版本一致的描述文件，无须照搬 ArtCraft 字段名。

验收：ArtCraft 能据此构造一个合法请求，并在提交前识别不支持的输入组合。不支持的能力不显示，不静默裁剪构图。

### 3.2 上传与输入引用

接口：`POST /api/upload`。

已知使用 multipart，涉及 `file`、`type` 和可选 `task_id`；请确认完整响应及调用顺序。

请提供：

- PNG 上传的最小请求与响应样例。
- 返回结果如何映射为 `FileMeta{task_id,name}`。
- `files` 中实际应使用哪个输入槽位名称。
- 无生成任务 ID 时如何上传；上传标识与最终生成任务如何关联。
- 文件大小、尺寸、格式限制，超限响应及素材保留期。
- 素材在排队及执行期间不会被提前清理的保证或续期规则。

验收：独立客户端可上传 PNG，并将平台返回的引用用于 playground 任务，无需共享磁盘、浏览器页面状态或 ArtCraft 云端上传。

### 3.3 创建独立任务

接口：`POST /api/playground/runs`。

沿用已有请求结构，不增加虚构的 `model_id`、`image_url` 等替代字段：

```text
mode        模板对应的 mode，取真实目录值
 template   模板 code，取真实目录值
prompt      动作提示词
params      选定模板的真实参数
files       输入槽位 → FileMeta 数组
batch_count 首期固定 1
```

请提供一份能实际执行的单图视频请求与响应样例，说明：

- 响应包装格式、PlaygroundRun 标识和用于查询的 `task_id`。
- 创建接口是否已启动执行，还是还需显式调用其他接口。
- 参数校验失败、模板停用、服务不可用时的状态码与错误结构。
- 默认参数及规范化行为；不得悄悄丢弃用于构图的图片输入。

验收：不传 project/scene/shot 即可提交并进入可查询状态。

### 3.4 状态查询

接口：`GET /api/tasks/:id`。

请提供：

- 真实状态枚举和终态分类；不要求改成 ArtCraft 命名。
- 排队、运行、成功、失败的脱敏响应样例。
- 进度字段单位和含义；没有百分比也可以，ArtCraft 显示不确定进度。
- 错误字段、未知任务响应、平台重启后的任务查询行为。
- 建议轮询间隔、限流与完成任务的保留期。

验收：只依靠查询就能判断成功、失败并找到结果；WebSocket 断开不能导致任务无法恢复。首期不强制新增 WebSocket 功能。

### 3.5 输出下载

已有路由基础：

- `GET /api/output/:gpu/*path`
- `GET /api/instances/:id/output/*path`

请确认选定模板应使用哪条路径，以及如何从任务输出字段得到实例、文件名和子目录等必要信息；无需为了 ArtCraft 另建下载服务。

请说明鉴权、返回 Content-Type、过期和删除行为、下载重试，以及多输出时哪个是主视频。

验收：ArtCraft 不依赖平台机器的本地绝对路径即可下载并播放视频。网络下载失败后可重新下载，不必重新生成。

### 3.6 地址、鉴权与兼容性

请确认受支持的服务地址配置、鉴权机制及部署前提。静态路由阅读没有证明部署无鉴权。

- 原生客户端应能使用已授权的服务凭据；不依赖人工操作网页会话。
- 允许开发环境按部署条件使用受信网络；不得建议无鉴权直接暴露公网。
- 不在 URL 或日志中传递凭据。
- 提供接口版本或交付版本标识；字段删除、状态语义变更应提前通知。
- 错误码、关联 ID 若已存在直接提供；不存在时先约定兼容的错误解析方式。

## 4. 可能需要平台新增的能力

以下均为条件性需求：请平台团队逐项反馈“已有 / 需新增 / 暂不支持”。不要把未确认当作确定缺失。

### R1：创建任务去重与丢失响应找回（P1，建议增强）

问题：服务创建成功但客户端没收到响应，直接重试可能重复占用 GPU。

建议在现有 playground 创建请求兼容增加客户端请求标识，或复用已有幂等机制。平台决定最终字段或请求头，不在此强制命名。

期望语义：

- 相同调用方、相同标识、相同请求返回同一结果，包括相同任务关联。
- 同一标识但请求不同返回明确冲突。
- 并发提交也不能重复调度。
- 明确保留时间及平台重启后的保证范围。
- 客户端可通过重放幂等创建或查询机制找回任务。

验收：模拟创建成功后响应丢失，重试或查回仍只产生一个生成任务。

可降级：首期没有此能力也可联调，但 ArtCraft 对结果不明的创建不自动重试，显示“提交状态待确认”，说明再次生成可能重复执行。不能承诺这一情况下绝不重复。

### R2：模板输入契约补齐（P0，仅当现有目录和文档不够用）

至少为首期选定模板提供 mode、参数与文件槽位定义。可补目录或随版本提供文档，不要求一次覆盖全部模型。

验收：对方提供的合法 fixture 请求通过，错误文件槽位、缺图、非法参数被拒绝且原因可解析。

### R3：可下载输出定位补齐（P0，仅当现有任务响应无法定位输出）

如当前输出只给本地路径，应补可通过现有下载接口定位的结构或受控 URL。不要把平台本地路径当桌面端共享路径。

验收：独立客户端根据任务响应与文档完成下载，无需猜测多个目录。

### R4：取消任务（P2，可选）

如尚无可靠接口，第一版不要求开发。ArtCraft 停止跟踪不等于取消生成。

若后续提供，应区分排队取消、运行中尽力终止和任务已经完成；明确返回状态与资源释放语义。

## 5. 明确留到后续的需求

项目、Scene、Shot 读取及候选回传另立需求，不纳入此次平台交付。

后续必须区分：上传文件、绑定目标镜头、候选审核、正式采用。预演不自动覆盖角色身份、正文事实或已审核素材；Scene 首尾帧字段不能代替 Shot 级候选绑定。

## 6. ArtCraft 团队承担的工作

- Stage3D 捕获、输入预览、参数校验与提交入口。
- 原生 HTTP 客户端、地址配置与凭据保护。
- 平台模板及状态映射，不静默回退云端生成。
- 持久化已知远端任务标识，重启恢复查询。
- 网络退避、提交状态不明的提示、下载失败单独重试。
- 输出下载安全校验、本地保存和 ArtCraft 内预览；图库导入作为独立操作，不强制上传云端。
- 模拟服务、客户端单元测试、UI 测试与联调记录。

以上是开发范围，不表示已实现。
